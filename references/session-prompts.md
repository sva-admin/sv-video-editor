# Reusable session prompts

These examples use generic project roles. Existing authorization and the actual brief take precedence over an example's wording.

## Resume

```text
Use SV Video Editor. Read the current handoff, accepted plan and latest render
record. Check whether any jobs are still running and which inputs changed.
Tell me the next useful action, then continue the work already authorized.
Reuse valid transcripts, proxies and contact sheets.
```

## Plan only

```text
Map the material we have into a coherent film. For each chapter, show the
message, source evidence, candidate shots, audio and connection to the next
chapter. Compare a direct introduction with a question-led opening only if
both are supported. Recommend one and identify the missing evidence.
Planning only for now; do not render or generate new footage.
```

## Build the proof

```text
Build the authorized representative rough cut with local tools. Choose a
sequence that tests speech continuity, mixed footage and the caption treatment.
Keep source files unchanged. Record exact source ranges and output frames.
Watch and listen to the encoded result and show unresolved issues clearly.
```

## Refine without changing the story

```text
Improve the approved cut's motion, crop, captions and audio. Preserve the
accepted story and complete spoken words. Change only what the notes require.
Compare retained sections and verify the actual new export, not just the plan.
```

## Repair a review panel

```text
Use the existing canonical records. Make the next decisions, assigned tasks,
waiting items and current render easy to find on one page. Identify stale
renders. Prevent old browser tabs from overwriting new edits. Keep internal
notes out of client-facing views and test seeking on the actual local server.
```

## Deliver

```text
Prepare the agreed deliverables and editable handoff. Check the final encoded
files, captions and source links. Separate technical results, watched and
listened coverage, and owner approvals. List missing checks directly.
Do not mark a deliverable sent or published unless that action happened.
```

## Capture a reusable lesson

```text
Document the failure, smallest correction and confirming evidence in this
project. Suggest a generic skill improvement with an invented test case.
Keep private details out and distinguish a verified method from a hypothesis.
Do not change persistent memory or publish the update without authorization.
```
